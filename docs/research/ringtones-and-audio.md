# Ringtones, preview and alarm audio playback per platform

Research note for issue [#6](https://github.com/IgorJonski/Snoozeloo/issues/6) (part of #1). Researched 2026-09-05 against primary sources only (developer.android.com, AOSP source, developer.apple.com, the WWDC25 session transcript, kotlinlang.org and the Compose Multiplatform library source). Every claim carries its URL; items the sources do not settle are marked **Unconfirmed**.

Project facts this note is written against: `minSdk = 30`, `compileSdk = 36`, Compose Multiplatform `1.11.1` (`gradle/libs.versions.toml`).

## Summary

- **Android** has everything the spec asks for. `RingtoneManager` enumerates the system alarm tones (`TYPE_ALARM`) with a title and a `content://` URI, and exposes the default. Playback at a *relative* volume is a first-class API on all three player options (`Ringtone.setVolume`, `MediaPlayer.setVolume`, Media3 `Player.setVolume`, all `0.0..1.0` scalars) and never touches the system alarm stream. `AudioAttributes.USAGE_ALARM` routes the sound to the alarm stream. Looping and vibration patterns (`VibrationEffect.createWaveform`, `VibrationAttributes.USAGE_ALARM`) are supported.
- **iOS 26 / AlarmKit** delivers the alert itself; the app only chooses *which* sound. `AlarmManager.AlarmConfiguration` takes a `sound:` of type ActivityKit `AlertConfiguration.AlertSound`, which is either `.default` or `.named("<file>")` where the file lives in the app's main bundle or in `Library/Sounds` of the app container. There is **no volume parameter and no vibration/haptics parameter** on the alarm configuration. Per-alarm volume is therefore only achievable for the in-app preview (`AVAudioPlayer.volume`), and the Vibrate toggle cannot influence the AlarmKit alert.
- **Preview** works the same way on both platforms: a player with a bounded clip and an explicit stop. On iOS the audio session must use the `.playback` category so the preview is audible with the Ring/Silent switch on; the default `.soloAmbient` is silenced by the switch.
- **Sharing sound files** via Compose Resources is feasible for the preview on both platforms and for the Android alarm. For the AlarmKit alarm the file must be reachable by *name* from the main bundle root or `Library/Sounds`; Compose packs resources into a `compose-resources/` sub-directory of the bundle, so the iOS build must additionally place (or copy at first launch) the files where AlarmKit looks. Use **`.wav` (Linear PCM)**: it is an accepted iOS alert container and AAPT2 stores `.wav` uncompressed by default, which `AssetManager.openFd` requires.

## Android details

### Enumerating `TYPE_ALARM` tones and the default

- `RingtoneManager.TYPE_ALARM` (= 4) is "sounds that are used for the alarm". Construct `RingtoneManager(context)` (or with an `Activity` so the cursor follows its lifecycle), call `setType(TYPE_ALARM)`, then `getCursor()`. The cursor "will be the same cursor returned each time … so do not `Cursor.close()`"; columns are `ID_COLUMN_INDEX` (0), `TITLE_COLUMN_INDEX` (1), `URI_COLUMN_INDEX` (2). `getRingtoneUri(position)` and `getRingtone(position)` map cursor rows to a `Uri`/`Ringtone`. "The list of ringtones available will differ depending on whether the caller has the `READ_EXTERNAL_STORAGE` permission." [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)
- Default: `getDefaultUri(TYPE_ALARM)` returns "the symbolic Uri which will resolved to the actual sound when played" (this is `Settings.System.DEFAULT_ALARM_ALERT_URI`, "a Uri that will point to the current default alarm alert at any given time"); `getActualDefaultRingtoneUri(context, TYPE_ALARM)` returns the concrete one; `isDefault(uri)` tests either form. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager), [Settings.System](https://developer.android.com/reference/android/provider/Settings.System)
- `getRingtone(context, uri)` "will attempt to fallback on another sound. If it cannot find any, it will return null" — a stored URI may stop resolving (user deleted a custom tone), so the contract needs a fallback to the default. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)
- The system picker (`ACTION_RINGTONE_PICKER`) models Silent as `EXTRA_RINGTONE_PICKED_URI == null` when `EXTRA_RINGTONE_SHOW_SILENT` is set; the app's own list can use the same "no URI" convention. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)
- `RingtoneManager.hasHapticChannels(context, uri)` reports whether a tone carries haptic channels. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)

### Playing at a relative volume with `USAGE_ALARM`

- `AudioAttributes.USAGE_ALARM` (API 21) is "the usage … an alarm (e.g. wake-up alarm)"; `CONTENT_TYPE_SONIFICATION` suits short tones. `FLAG_AUDIBILITY_ENFORCED` is *not* for alarms: it "should only be used for sounds subject to regulatory behaviors in some countries, such as for camera shutter sound". [AudioAttributes](https://developer.android.com/reference/android/media/AudioAttributes)
- `AudioManager.STREAM_ALARM` "identif[ies] the volume of audio streams for alarms"; `setStreamVolume` changes the user's setting for *all* streams of that type — that is the thing the spec forbids, and `MediaPlayer` docs explicitly recommend the per-player scalar instead. [AudioManager](https://developer.android.com/reference/android/media/AudioManager), [MediaPlayer](https://developer.android.com/reference/android/media/MediaPlayer)
- Three viable players (all available at minSdk 30):
  - **`Ringtone`** — `setAudioAttributes(attrs)` (API 21; `setStreamType` deprecated), `setLooping(bool)` and `setVolume(float)` (both API 28; "a raw scalar in range 0.0 to 1.0, where 0.0 mutes this player, and 1.0 corresponds to no attenuation"), `play()`, `stop()`, `isPlaying()`, `getTitle(context)`, `setHapticGeneratorEnabled` (API 31). No completion callback. Simplest for `content://` tones. [Ringtone](https://developer.android.com/reference/android/media/Ringtone)
  - **`MediaPlayer`** — `setAudioAttributes` "must [be called] before `prepare()`/`prepareAsync()`"; `setDataSource(Context, Uri)` for content URIs, `setDataSource(AssetFileDescriptor)` (API 24) for bundled assets; `setLooping`; `setVolume(l, r)` "raw scalars in range 0.0 to 1.0. UI controls should be scaled logarithmically". Has `setOnCompletionListener`. [MediaPlayer](https://developer.android.com/reference/android/media/MediaPlayer)
  - **Media3 `ExoPlayer`** — `ExoPlayer.Builder.setAudioAttributes(attrs, handleAudioFocus)`: "If audio focus should be handled, the usage must be `USAGE_MEDIA` or `USAGE_GAME`. Other usages will throw an `IllegalArgumentException`" — so with `C.USAGE_ALARM` pass `handleAudioFocus = false` and manage focus yourself. `Player.setVolume` is "between 0 (silence) and 1 (unity gain)"; `REPEAT_MODE_ONE` "repeats the currently playing `MediaItem` infinitely". `DefaultDataSource` reads `file:`, `asset:///…` (APK assets), `content:` and `rawresource:` URIs. [ExoPlayer.Builder](https://developer.android.com/reference/androidx/media3/exoplayer/ExoPlayer.Builder), [Player](https://developer.android.com/reference/androidx/media3/common/Player), [DefaultDataSource](https://developer.android.com/reference/androidx/media3/datasource/DefaultDataSource)
- Volume mapping: the spec's 0–100 % maps to the `0.0..1.0` scalar; per the `MediaPlayer` note, apply a logarithmic (perceptual) curve rather than a linear one.
- **Audio focus**: `AudioFocusRequest.Builder(focusGain)` accepts `AUDIOFOCUS_GAIN_TRANSIENT` and `AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`; set the same `USAGE_ALARM` attributes on the request "as used for playback". The focus guide does not mention alarms, so requesting focus while ringing is good citizenship (pauses music) rather than a documented requirement — **Unconfirmed** that the platform ducks/pauses other apps automatically for `USAGE_ALARM` playback without a request. On Android 15+ `requestAudioFocus` is only granted to the top app or an app with a foreground service; the ringing screen/full-screen activity or a foreground service satisfies that. [AudioFocusRequest.Builder](https://developer.android.com/reference/android/media/AudioFocusRequest.Builder), [Audio focus guide](https://developer.android.com/media/optimize/audio-focus)
- Do Not Disturb has a dedicated `PRIORITY_CATEGORY_ALARMS` (API 28) in `NotificationManager.Policy`; whether the alarm stream is audible under DND is the user's policy, not the app's. [NotificationManager.Policy](https://developer.android.com/reference/android/app/NotificationManager.Policy)

### Preview playback and stopping

- Use the same attributes (`USAGE_ALARM`) so the preview reflects alarm-stream loudness and the per-alarm scalar. Start with `play()`; stop with `stop()` after a fixed window (`Ringtone` has no completion callback, so the preview timer lives in the ViewModel/coroutine), when another tone is tapped, and when the screen leaves composition. `MediaPlayer.stop()` requires `prepare()` again before replay; `Media3.stop()` moves to `STATE_IDLE` and needs `prepare()` too; `Ringtone` can simply `play()` again. [Ringtone](https://developer.android.com/reference/android/media/Ringtone), [MediaPlayer](https://developer.android.com/reference/android/media/MediaPlayer), [Player](https://developer.android.com/reference/androidx/media3/common/Player)

### Vibration patterns while ringing

- `VibrationEffect.createWaveform(long[] timings, int repeat)` (API 26): timings alternate off/on starting with off ("the first timing value will often be 0"); `repeat` is the index to loop from or `-1`; "Repeating effects will be played indefinitely and should be cancelled via `Vibrator.cancel()`". The amplitude overload takes 0–255 per segment; `DEFAULT_AMPLITUDE` = -1; `hasAmplitudeControl()` tells whether amplitudes are honoured. [VibrationEffect](https://developer.android.com/reference/android/os/VibrationEffect), [Vibrator](https://developer.android.com/reference/android/os/Vibrator)
- Getting a vibrator: `Context.VIBRATOR_MANAGER_SERVICE` → `VibratorManager.getDefaultVibrator()` on API 31+ (`VIBRATOR_SERVICE` deprecated in 31); `Context.VIBRATOR_SERVICE` on API 30. `hasVibrator()` guards devices without one. Requires `android.permission.VIBRATE`. [VibratorManager](https://developer.android.com/reference/android/os/VibratorManager), [Vibrator](https://developer.android.com/reference/android/os/Vibrator)
- Attributes: `VibrationAttributes.USAGE_ALARM` (API 30) "for alarm vibrations"; `VibrationAttributes.createForUsage(USAGE_ALARM)` is API 33, as is `Vibrator.vibrate(VibrationEffect, VibrationAttributes)`. On API 30–32 use `vibrate(VibrationEffect, AudioAttributes)` (API 26, deprecated in 33) with `USAGE_ALARM` audio attributes. The usage matters: "The app should be in the foreground for the vibration to happen. Background apps should specify a ringtone, notification or alarm usage in order to vibrate." [VibrationAttributes](https://developer.android.com/reference/android/os/VibrationAttributes), [Vibrator](https://developer.android.com/reference/android/os/Vibrator)
- Optional audio-coupled haptics: `Ringtone.setHapticGeneratorEnabled(true)` / `HapticGenerator.isAvailable()` (API 31). [Ringtone](https://developer.android.com/reference/android/media/Ringtone), [HapticGenerator](https://developer.android.com/reference/android/media/audiofx/HapticGenerator)

### Bundled sound files on Android

- `AssetManager.openFd(name)` opens "an uncompressed asset by mmapping it … The asset must be uncompressed, or an exception will be thrown." [AssetManager](https://developer.android.com/reference/android/content/res/AssetManager)
- AAPT2 stores these extensions uncompressed by default: `.jpg .jpeg .png .gif .webp`, `.wav .mp2 .mp3 .ogg .aac .mid .midi .smf .jet .rtttl .imy .xmf .amr .awb`, `.mpg .mpeg .mp4 .m4a .m4v .3gp .3gpp .3g2 .3gpp2 .wma .wmv .webm .mkv`. **`.caf` and `.aiff` are not in the list.** [aapt2 Link.cpp](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/tools/aapt2/cmd/Link.cpp)
- AGP: `androidResources.noCompress` (`MutableCollection<String>`, AGP 7.0+; the `aaptOptions` block and the `noCompress(...)` functions are deprecated) adds extensions "to be stored uncompressed in the APK". Only needed if a non-default extension such as `.caf` is shipped. [AndroidResources DSL](https://developer.android.com/reference/tools/gradle-api/8.9/com/android/build/api/dsl/AndroidResources)

## iOS details

### AlarmKit alert sound

- AlarmKit (iOS 26.0+) alarms "break through the silent mode and the current focus"; the app needs `NSAlarmKitUsageDescription` (empty or missing → "your app can't schedule alarms") and `AlarmManager.requestAuthorization()`. [AlarmKit](https://developer.apple.com/documentation/alarmkit), [NSAlarmKitUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsalarmkitusagedescription), [Scheduling an alarm](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit)
- `AlarmManager.AlarmConfiguration` — `init(countdownDuration:schedule:attributes:stopIntent:secondaryIntent:sound:)`, `.alarm(schedule:attributes:stopIntent:secondaryIntent:sound:)`, `.timer(...)` (plus `appEntityIdentifier:` variants). The `sound` parameter is "The sound to play when the alarm fires"; examples pass `sound: .default`. **These are all the parameters — there is no volume, vibration or haptics parameter.** [AlarmConfiguration](https://developer.apple.com/documentation/alarmkit/alarmmanager/alarmconfiguration), [init](https://developer.apple.com/documentation/alarmkit/alarmmanager/alarmconfiguration/init(countdownduration:schedule:attributes:stopintent:secondaryintent:sound:)), [alarm(...)](https://developer.apple.com/documentation/alarmkit/alarmmanager/alarmconfiguration/alarm(schedule:attributes:stopintent:secondaryintent:sound:)), [Alarm](https://developer.apple.com/documentation/alarmkit/alarm)
- The sound type is ActivityKit's `AlertConfiguration.AlertSound` — WWDC25 session 230: "Because AlarmKit uses ActivityKit for alarm presentation, you can define a custom sound by using its AlertSound struct. You will need to specify the name of the sound file, which should be either in your app's main bundle or Library/Sounds folder of your app's data container." Code: `AlertConfiguration.AlertSound.named("Chime")`. [WWDC25 230](https://developer.apple.com/videos/play/wwdc2025/230/), [AlertSound](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound), [named(_:)](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound/named(_:))
- `AlertSound` has exactly two members: `default` and `named(_:)`. No "none", no volume. [AlertSound](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound)
- Format/length: the `AlertSound` pages say nothing beyond location. The system-sound rules documented for `UNNotificationSound` (same locations: `Library/Sounds` in the app container, `Library/Sounds` in a group container, or the main bundle) are: Linear PCM, MA4 (IMA/ADPCM), µLaw, aLaw in `aiff`/`wav`/`caf`; "Sound files must be less than 30 seconds in length. If the sound file is longer than 30 seconds, the system plays the default sound instead." `afconvert … -d ima4 -f caff` converts. **Unconfirmed** that AlarmKit enforces the same 30 s cap or that it loops the file until dismissed; designing to the `UNNotificationSound` rules is the conservative choice. [UNNotificationSound](https://developer.apple.com/documentation/usernotifications/unnotificationsound), [init(named:)](https://developer.apple.com/documentation/usernotifications/unnotificationsound/init(named:))
- Volume: the only Apple API that takes an alert volume is `UNNotificationSound.defaultCriticalSound(withAudioVolume:)` for critical alerts, which "require a special entitlement issued by Apple" and are not part of AlarmKit. Conclusion: **per-alarm alert volume is not possible on iOS**. (Baking attenuation into pre-rendered file variants is an implementation trick, not a documented capability — **Unconfirmed**.) [defaultCriticalSound(withAudioVolume:)](https://developer.apple.com/documentation/usernotifications/unnotificationsound/defaultcriticalsound(withaudiovolume:))
- Vibration: no parameter on `AlarmConfiguration`; Core Haptics stops the engine "because the user has put your app in the background" (`applicationSuspended`), and `UIFeedbackGenerator` is UI feedback for the foreground app. Whether the system vibrates for an AlarmKit alert by default is **Unconfirmed** (not documented). The Vibrate toggle therefore has no effect on the iOS alert. [Preparing your app to play haptics](https://developer.apple.com/documentation/corehaptics/preparing-your-app-to-play-haptics), [UIFeedbackGenerator](https://developer.apple.com/documentation/uikit/uifeedbackgenerator)
- Presentation note: `AlarmPresentation.Alert(title:stopButton:…)` is deprecated; "The system provides a stop button automatically", the app may add one secondary button (`.countdown` = repeat/snooze via `postAlert`, `.custom` = open app). [AlarmPresentation.Alert](https://developer.apple.com/documentation/alarmkit/alarmpresentation/alert-swift.struct)

### In-app preview with `AVAudioPlayer`

- `AVAudioPlayer(contentsOf:)` / `init(data:)`; `prepareToPlay()` "activates the audio session"; `play()`, `stop()` ("undoes the setup … doesn't reset `currentTime`"), `isPlaying`; `volume` 0.0–1.0 "relative to other audio output"; `setVolume(_:fadeDuration:)`; `numberOfLoops` (negative = loop "until you call `stop()`"); delegate `audioPlayerDidFinishPlaying`. [AVAudioPlayer](https://developer.apple.com/documentation/avfaudio/avaudioplayer), [volume](https://developer.apple.com/documentation/avfaudio/avaudioplayer/volume), [numberOfLoops](https://developer.apple.com/documentation/avfaudio/avaudioplayer/numberofloops), [prepareToPlay()](https://developer.apple.com/documentation/avfaudio/avaudioplayer/preparetoplay()), [stop()](https://developer.apple.com/documentation/avfaudio/avaudioplayer/stop())
- Audio session category: the default `.soloAmbient` — "Your audio is silenced by screen locking and by the Silent switch"; `.ambient` likewise. `.playback` — "your app audio continues with the Silent switch set to silent or when the screen locks"; it is non-mixable by default (use `.mixWithOthers` to avoid interrupting music); background continuation needs `UIBackgroundModes: audio`, which a short foreground preview does not need. Set `AVAudioSession.sharedInstance().setCategory(.playback)` before previewing. [soloAmbient](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/soloambient), [ambient](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/ambient), [playback](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)

## Sharing sound files through Compose Resources

- Raw files go under `composeResources/files/…`; `suspend fun Res.readBytes(path): ByteArray` reads them; `Res.getUri(path)` "contains the absolute path to the file" for other libraries; "Starting with Compose Multiplatform 1.7.0, all multiplatform resources are packed into Android assets", enabling "direct access from WebViews and media player components on Android". [CMP resources usage](https://kotlinlang.org/docs/multiplatform/compose-multiplatform-resources-usage.html)
- Android implementation: `getUri` returns `file:///android_asset/<path>` when the asset exists (else a class-loader URI); `readBytes` streams via `AssetManager.open`. Strip the `file:///android_asset/` prefix to get the asset name for `assets.openFd(name)` → `MediaPlayer.setDataSource(AssetFileDescriptor)`, or use Media3's `asset:///<name>` scheme. Both require the asset to be uncompressed (see AAPT2 list above). [ResourceReader.android.kt](https://github.com/JetBrains/compose-multiplatform/blob/master/components/resources/library/src/androidMain/kotlin/org/jetbrains/compose/resources/ResourceReader.android.kt), [AssetManager](https://developer.android.com/reference/android/content/res/AssetManager), [DefaultDataSource](https://developer.android.com/reference/androidx/media3/datasource/DefaultDataSource)
- iOS implementation: `getUri` returns `NSURL.fileURLWithPath(...)` for `<mainBundle.resourcePath>/compose-resources/<path>` (or `<Frameworks/*.framework>/composeResources/<path>`); `readBytes` reads via `NSFileManager`. `AVAudioPlayer(contentsOf: URL(string: uri))` works directly. [ResourceReader.ios.kt](https://github.com/JetBrains/compose-multiplatform/blob/master/components/resources/library/src/iosMain/kotlin/org/jetbrains/compose/resources/ResourceReader.ios.kt)
- AlarmKit gap: `AlertSound.named` resolves a *name* in the main bundle or `Library/Sounds`; the docs do not say sub-directories of the bundle are searched, so a file at `compose-resources/files/x.wav` is **Unconfirmed** to be found by `.named("x.wav")`. Two documented-safe options: (a) also add the files to the iOS target's Copy Bundle Resources so they sit at the bundle root; (b) on first launch copy `Res.readBytes(...)` into `<container>/Library/Sounds/<name>` and reference that name — `Library/Sounds` is an explicitly documented search location. [named(_:)](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound/named(_:)), [UNNotificationSound](https://developer.apple.com/documentation/usernotifications/unnotificationsound)
- Format choice for one shared set: `.wav` containing Linear PCM (or IMA4 in `.caf` for size, but then add `noCompress += "caf"` on Android). `.wav` is accepted by iOS alert sounds and is in AAPT2's default no-compress list.

## Constraints the Ringtone contract must respect

1. **Ringtone identity is platform-specific and opaque.** Android: a `content://` URI string (plus the symbolic default URI). iOS: a bundled file name (or "default"). The common model should carry `id: String`, `displayName: String`, `isDefault: Boolean`, `isSilent: Boolean`, and let each platform interpret `id`. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager), [AlertSound](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound)
2. **Stored Android URIs can stop resolving**; `getRingtone` falls back or returns `null`, so the contract needs a "resolve or fall back to default" step at ring time and when rendering the list. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)
3. **Volume is a `0.0..1.0` player scalar, never a system stream index.** Android applies it to both preview and alarm (`Ringtone`/`MediaPlayer`/Media3 `setVolume`); UI 0–100 % should map through a logarithmic curve. On iOS it applies to the preview only — the AlarmKit alert has no volume input. The contract must allow "volume not applicable to the alert on this platform" (hide/disable or label as preview-only). [MediaPlayer](https://developer.android.com/reference/android/media/MediaPlayer), [AlarmConfiguration.init](https://developer.apple.com/documentation/alarmkit/alarmmanager/alarmconfiguration/init(countdownduration:schedule:attributes:stopintent:secondaryintent:sound:))
4. **Vibrate is Android-only in effect.** Android: a repeating `VibrationEffect` with `USAGE_ALARM` attributes, cancelled explicitly on stop/snooze. iOS: no API on the AlarmKit alert; the toggle must be either hidden or documented as no-op on iOS. [Vibrator](https://developer.android.com/reference/android/os/Vibrator), [Preparing your app to play haptics](https://developer.apple.com/documentation/corehaptics/preparing-your-app-to-play-haptics)
5. **Silent means "no sound source", not volume 0.** Android: skip the player entirely, keep vibration if enabled. iOS: `AlertSound` has no "none" case; either ship a silent `.wav` (**Unconfirmed** to be honoured) or fall back to `.default` for the alert and treat Silent as preview-only. [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager), [AlertSound](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound)
6. **Alarm playback attributes are fixed**: `USAGE_ALARM` + `CONTENT_TYPE_SONIFICATION`, looping on, no `FLAG_AUDIBILITY_ENFORCED`; with Media3 `handleAudioFocus` must be `false` (`USAGE_ALARM` throws otherwise) and focus is requested manually with the same attributes. [AudioAttributes](https://developer.android.com/reference/android/media/AudioAttributes), [ExoPlayer.Builder](https://developer.android.com/reference/androidx/media3/exoplayer/ExoPlayer.Builder)
7. **Preview is bounded and single-instance**: one active preview at a time, stopped on tap of another tone, on leaving the screen, and after a fixed clip length (the `Ringtone` API has no completion callback). iOS preview must set `AVAudioSession` category `.playback` first or it is muted by the Ring/Silent switch. [Ringtone](https://developer.android.com/reference/android/media/Ringtone), [playback](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)
8. **Bundled sound files** must satisfy the iOS alert rules — Linear PCM/IMA4/µLaw/aLaw in `aiff`/`wav`/`caf`, under 30 s — and, on Android, be stored uncompressed (`.wav` is by default; anything else needs `androidResources.noCompress`). [UNNotificationSound](https://developer.apple.com/documentation/usernotifications/unnotificationsound), [aapt2 Link.cpp](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/tools/aapt2/cmd/Link.cpp), [AndroidResources DSL](https://developer.android.com/reference/tools/gradle-api/8.9/com/android/build/api/dsl/AndroidResources)
9. **iOS alert files must be reachable by name from the bundle root or `Library/Sounds`**; Compose Resources place them under `compose-resources/…`, so the iOS side must copy them (Copy Bundle Resources, or first-launch copy into `Library/Sounds`). The contract's iOS `id` should be the file *name* AlarmKit will be given, not the Compose URI. [named(_:)](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound/named(_:)), [ResourceReader.ios.kt](https://github.com/JetBrains/compose-multiplatform/blob/master/components/resources/library/src/iosMain/kotlin/org/jetbrains/compose/resources/ResourceReader.ios.kt)
10. **API-level branches on Android (minSdk 30)**: `VibratorManager` needs 31 (`VIBRATOR_SERVICE` on 30); `Vibrator.vibrate(effect, VibrationAttributes)` and `createForUsage` need 33 (use the `AudioAttributes` overload on 30–32); `Ringtone.setVolume/setLooping` (28) and `VibrationAttributes.USAGE_ALARM` (30) are always available. [VibratorManager](https://developer.android.com/reference/android/os/VibratorManager), [VibrationAttributes](https://developer.android.com/reference/android/os/VibrationAttributes), [Ringtone](https://developer.android.com/reference/android/media/Ringtone)
11. **Permissions/manifest**: Android `VIBRATE`; optionally `READ_EXTERNAL_STORAGE`-class access changes which tones `getCursor()` lists. iOS `NSAlarmKitUsageDescription` plus runtime authorization, and a widget extension if a countdown presentation is used ("Otherwise, the system may unexpectedly dismiss alarms and fail to alert"). [Vibrator](https://developer.android.com/reference/android/os/Vibrator), [RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager), [Scheduling an alarm](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit)
